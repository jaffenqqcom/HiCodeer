# Zed 官方服务依赖分析（HiCodeer / OHOS 视角）

> 归档：2026-09-17。
>
> **本文目的**：一次把「HiCodeer 到底会不会连到 zed 官方服务器、连了做什么、不连会损失什么」查清并固化，
> 后续不再重复分析。所有结论均给出 `file:line`，可直接复核。
>
> **「官方服务」的范围**：`zed.dev` 及其子域 `api.zed.dev`（API）、`cloud.zed.dev`（Cloud/LLM/发布资产）、
> `llm-staging.zed.dev` / `api-staging.zed.dev`（staging）。不含第三方（GitHub、nodejs.org、npm registry、各模型厂商）。

---

## 0. 结论速览

1. **全应用只有一个 HTTP 基址开关**：`ClientSettings.server_url`，默认 `https://zed.dev`，
   构造点唯一（`crates/client/src/client.rs:586`）。它下面同时挂着 6 类官方服务：扩展市场、协作、
   遥测、自动更新、账号/系统设置、AI。改它一个值，6 类服务一起改向。

2. **不登录 Zed 账号时，真正会主动发起的官方请求只有两条**：
   - 遥测（默认开，不需要凭据，直接发 `api.zed.dev/telemetry/events`）；
   - 扩展市场（用户主动打开扩展面板时才发）。
   其余（AI、账号、协作、反馈）都要求凭据，未登录的路径上不会触发。

3. **要「完全不碰 zed 官方服务」，最小改动是 3 个默认值**（遥测开关、agent 默认模型 provider、
   edit prediction provider），都能在 OHOS 叠加层里覆盖；**不需要**动代码。若要连协作一起断，
   另加第 4 节的 collab 移除改动（那部分必须用 `#[cfg(target_env = "ohos")]`，因为它删的是共享键）。

4. **AI 的强依赖只有三处**：Zed AI（Cloud provider）、Zed 编辑预测（Zeta 模型）、内置 web search。
   换成 BYOK 直连后，失去的正是这三项 + 反馈提交 + 账单/试用页面 + 服务端下发的 feature flags，
   其余 AI 能力（十多家 provider、Agent 面板本体、MCP、规则文件）全部保留。

5. **一件事做不到**：Zeta 是 zed 私有模型权重，即使自建一套 Zed 协议兼容服务端，也拿不到编辑预测的
   Zed provider。这一项在脱离 zed 之后是**必然失去**的。

## 1. 总开关：唯一的 HTTP 基址

### 1.1 构造点唯一

全仓库只有一处构造 `HttpClientWithUrl`（带 base URL 的 HTTP 客户端）：

```
crates/client/src/client.rs:586
    let http = Arc::new(HttpClientWithUrl::new_url(
        cx.http_client(),
        &ClientSettings::get_global(cx).server_url,
        cx.http_client().proxy().cloned(),
    ));
```

base URL 的来源：

- 设置项 `server_url`，默认值 `"https://zed.dev"`（`assets/settings/default.json:2687`）；
- 环境变量 `ZED_SERVER_URL` 优先级更高，会覆盖设置项
  （`crates/client/src/client.rs:63-64` 读取，`:119-126` 应用）。

### 1.2 三个 URL 构建器的映射规则

三个构建器都以 base URL 作输入做白名单映射（`crates/http_client/src/http_client.rs:277-330`）：

```text
build_zed_api_url(path)            // http_client.rs:277
    base "https://zed.dev"            -> https://api.zed.dev
    base "https://staging.zed.dev"    -> https://api-staging.zed.dev
    base "http://localhost:3000"      -> http://localhost:8080
    base <other>                      -> <other>            // passthrough

build_zed_cloud_url(path)          // http_client.rs:293
build_zed_cloud_url_with_query()   // http_client.rs:306
    base "https://zed.dev"            -> https://cloud.zed.dev
    base "https://staging.zed.dev"    -> https://cloud.zed.dev
    base "http://localhost:3000"      -> http://localhost:8787
    base <other>                      -> <other>            // passthrough

build_zed_llm_url(path)            // http_client.rs:319
    base "https://zed.dev"            -> https://cloud.zed.dev
    base "https://staging.zed.dev"    -> https://llm-staging.zed.dev
    base "http://localhost:3000"      -> http://localhost:8787
    base <other>                      -> <other>            // passthrough
```

关键性质：**遇到非白名单值（即自建域名）时三者都原样使用该域名**。也就是说，一台自建服务器要同时
扮演 API、Cloud、LLM 三个角色。

### 1.3 推论

- 改 `server_url` 一处 = 扩展市场 + 协作 + 遥测 + 自动更新 + 账号 + AI 一起改向。
- 自建服务器**必须实现全套端点**，否则各功能会静默失效（各自有各自的错误日志，但都不阻塞应用启动）。
- 反过来：只要不碰 `server_url`，任何功能想连官方就一定会连官方，没有第二个旁路。

## 2. 服务依赖清单（AI 之外）

以下逐条给出：端点 → 客户端调用点 → 触发条件 → 凭据要求 → 默认值 → OHOS 现状。

### 2.1 遥测 telemetry

- **端点**：`POST https://api.zed.dev/telemetry/events`
  （`crates/client/src/telemetry.rs:652`，走 `build_zed_api_url`）。
- **客户端调用链**：`telemetry::event!` 宏 → `report_event` → 入队 → 定时 `flush_events` → `flush_events_inner`。
  - 入队门控：`if !state.settings.metrics { return; }`（`crates/client/src/telemetry.rs:571`）。
- **凭据要求**：**无**。不带登录 token 也会发（只带 `system_id` / `installation_id` /
  `session_id` / `metrics_id` / `is_staff` / app_version / os_name）。
- **默认值**：`assets/settings/default.json:1561-1565`：

  ```json
  "telemetry": {
      "diagnostics": true,
      "metrics": true
  }
  ```

- **OHOS 现状**：`assets/settings/default-ohos.json` **没有**覆盖 telemetry →
  **当前 OHOS 构建默认开启遥测并会向 api.zed.dev 发送**。
- **可选校验**：官方构建会注入编译期常量 `ZED_CLIENT_CHECKSUM_SEED`
  （`crates/client/src/telemetry.rs:82-90`，`has_checksum_seed()` 见 `:352-354`）用于计算
  `x-zed-checksum` 头。OHOS 构建脚本未注入 → 校验值为空，服务端是否接收取决于服务端策略。
  这一点不影响「会不会发」的结论。
- **落盘**：事件还会写本地 `logs/telemetry.log`（见 `2026-09-14-ohos-data-root-layout.md`）。
- **处置方式（二选一，都不需要改代码）**：
  - 在 `assets/settings/default-ohos.json` 覆盖 `telemetry.metrics = false`；
  - 或同时把 `diagnostics` 也置 false（`diagnostics` 控制崩溃相关诊断信息的收集）。

### 2.2 崩溃上报 minidump

- **端点**：来自编译期/环境变量 `MINIDUMP_ENDPOINT`
  （`crates/client/src/telemetry.rs:92-96`，`option_env!("ZED_MINIDUMP_ENDPOINT")` 优先，
  否则读同名环境变量）。
- **启用条件**：`should_install_crash_handler()`（`crates/client/src/telemetry.rs:98-102`）：

  ```text
  channel == Dev 且 ZED_GENERATE_MINIDUMPS 设置  -> true
  或 channel != Dev 且 MINIDUMP_ENDPOINT 存在    -> true
  ```

- **上传实现**：`crates/zed/src/reliability.rs:273-430`（multipart 上传，字段名
  `upload_file_minidump`，附 sentry 风格的 contexts 字段）。历史 minidump 会在下次启动时补传
  （`crates/zed/src/reliability.rs:232-259`）。
- **OHOS 现状**：构建脚本未注入 `ZED_MINIDUMP_ENDPOINT`，且 `RELEASE_CHANNEL=dev` →
  **崩溃处理器不安装，minidump 不上传**，只落本地磁盘。**当前不构成依赖**。
- **注意**：若将来把 channel 改成 stable 并注入 endpoint，这条会立刻变成活跃依赖。

### 2.3 自动更新 auto_update

- **端点**：`GET https://cloud.zed.dev/releases/{channel}/{version}/asset`
  （`crates/auto_update/src/auto_update.rs:673`，走 `build_zed_cloud_url_with_query`，
  查询参数含 os/arch/asset/metrics_id/system_id/is_staff）。
- **触发条件**：`AutoUpdater::start_polling`，仅当
  `ReleaseChannel::poll_for_updates()` 为真（`crates/auto_update/src/auto_update.rs:276-295`），
  而该方法在 Dev 通道返回 false（`crates/release_channel/src/lib.rs:201-203`：

  ```rust
  pub fn poll_for_updates(&self) -> bool {
      !matches!(self, ReleaseChannel::Dev)
  }
  ```

  ）。
- **当前通道**：`crates/zed/RELEASE_CHANNEL` 内容为 `dev` →
  **不会自动轮询**。但 `auto_update::init` 仍然被调用（`crates/zed/src/main.rs:682`），
  用户在菜单里手动触发 Check for Updates 时仍会发请求。
- **相关**：发布资产的下载 URL 也由该 API 返回；Windows WSL 沙箱直接用
  `https://cloud.zed.dev/releases/$channel/$version/download?asset=zed&...`
  （`crates/sandbox/src/windows_wsl.rs:121`，与 OHOS 无关）。
- **处置方式**：若要彻底不请求，需隐藏/禁用菜单项（属代码改动，非配置）。

### 2.4 账号 / 组织 / 系统设置 / feature flags

这一组都走 `cloud_api_client` + `client`，**全部要求已登录凭据**。

- **端点与调用点**：
  - `GET /client/users/me`（`crates/cloud_api_client/src/cloud_api_client.rs:116`、`:244`）
  - `POST /client/llm_tokens`（`crates/cloud_api_client/src/cloud_api_client.rs:137`，铸 LLM token）
  - `POST /client/system_settings`（`crates/cloud_api_client/src/cloud_api_client.rs:161`）
  - `GET /client/users/me`（校验凭据，`crates/cloud_api_client/src/cloud_api_client.rs:240-270`）
  - `POST /internal/users/impersonate`（`crates/client/src/client.rs:1580`，staff 模拟用）
  - WebSocket `/client/users/connect`（`crates/cloud_api_client/src/websocket/native.rs:66`、
    `crates/cloud_api_client/src/websocket/web.rs:58`）
  - 账号页 / 试用页 / 升级页由 base URL 拼出（`crates/client/src/zed_urls.rs:32-47`）
- **云端 websocket 的功能面极小**：协议只有一条消息
  （`crates/cloud_api_types/src/websocket_protocol.rs:12-15`）：

  ```rust
  pub enum MessageToClient {
      /// The user was updated and should be refreshed.
      UserUpdated,
  }
  ```

  编码为 CBOR（`ciborium`，`:18-27`）。用途是「账号信息变更时通知客户端刷新」。
- **feature flags**：并不单独拉取，而是搭着这条连接下发
  （`crates/feature_flags/src/feature_flags.rs:232-234` → `store.update_server_flags(staff, flags)`）。
  本地可用 `feature_flags` 设置兜底。
- **触发条件**：`Client::connect` 的调用点只出现在用户主动登录/分享/加入频道等路径：
  - `crates/client/src/client.rs:705`（user store 的 sign in 路径）
  - `crates/collab_ui/src/collab_panel.rs:2751`
  - `crates/project/src/project.rs:1695`（分享项目）
  - `crates/zed/src/main.rs:1339`（CLI 带 `--join-channel` / channel notes URL 启动）
  - **未登录账号时不会主动建立长连接**。
- **处置方式**：不需要动代码——只要不登录、不分享、不加入频道，就不会发请求。
  若把协作整体移除（第 4 节），这些触发点也随之消失。

### 2.5 反馈提交

- **端点**：
  - `POST /client/feedback/agent_thread`（`crates/cloud_api_client/src/cloud_api_client.rs:275`，
    实现 `submit_agent_feedback` `:272`）
  - `POST /client/feedback/agent_thread_comments`（`:290`，`submit_agent_feedback_comments` `:284`）
  - `POST /client/feedback/edit_prediction`（`:305`，`submit_edit_prediction_feedback` `:299`）
- **触发条件**：用户在 Agent 面板点「提交反馈」/对编辑预测结果点踩并附言。
- **OHOS 现状**：需要登录凭据才可用；未登录时功能报错但无副作用。

### 2.6 MCP OAuth 的 client-id metadata 文档

- **端点**：`https://zed.dev/oauth/client-metadata.json`
  （`crates/context_server/src/oauth.rs:37`，常量名 `CIMD_URL`）。
- **用途**：MCP 服务器走 OAuth 授权时，把该 URL 作为 OAuth client 的 `client_id`
  （CIMD = Client ID Metadata Document，OAuth 草案机制）。
- **替换方式**：自托管一份同名 JSON 即可，属「可替换」而非「强绑定」。

### 2.7 纯外链（不是功能依赖，只影响「点开链接」）

这些只出现在 UI 的 `open_url` 或报错提示文本里，不构成服务依赖，**不需要处置**：

- 文档站：`https://zed.dev/docs/*`（`crates/zed/src/zed.rs:114` 定义 `DOCS_URL`，
  另有 `crates/editor/src/hover_links.rs`、`crates/extensions_ui/src/extensions_ui.rs`、
  `crates/debugger_ui/src/debugger_panel.rs:651`、agent 工具文档链接等大量引用）
- `https://status.zed.dev`（`crates/zed/src/zed.rs:115`）
- `https://merch.zed.dev/`（`crates/zed/src/zed.rs:116`）
- `https://zed.dev/releases`（`crates/edit_prediction/src/zeta.rs:675` 的「Update Zed」按钮）
- `https://zed.dev/docs/ai/privacy-and-security`
  （`crates/edit_prediction_ui/src/edit_prediction_button.rs:57`）
- OpenRouter 请求头的 `HTTP-Referer` / `X-Title` 填字符串 `"https://zed.dev"`
  （`crates/open_router/src/open_router.rs:532`、`:558`）——仅标识来源，可保留。
- 测试夹具/断言里的 zed.dev 字符串（如 `crates/terminal/src/terminal.rs:4820`、
  `crates/git/src/repository.rs:4144`、`crates/migrator/src/migrator.rs:1278`）——非功能代码。

## 3. 扩展市场（extension marketplace）

### 3.1 端点全集

**客户端侧**（`crates/extension_host/src/extension_host.rs`）：

- `GET /extensions`（列表，`:574-598` 的 `fetch_extensions`，实际请求构造在 `:732` 的 `fetch`）
- `GET /extensions/{id}/download`（`:896`）
- `GET /extensions/{id}/{version}/download`（`:941`）
- 都经 `build_zed_api_url` → `https://api.zed.dev`

**服务端侧**（`crates/collab/src/api/extensions.rs`，可作协议参照）：

- 路由注册在 `:19-31`：`/extensions/updates`、`/extensions/:extension_id`、
  `/extensions/:extension_id/download`、`/extensions/:extension_id/:version/download`
- 归档在 blob store 里的键格式：`extensions/{id}/{version}/archive.tar.gz`（`:165`）
- 通过 S3 blob-store 轮询/发布（`:205-235`）

**数据结构**：`crates/cloud_api_types/src/extension.rs`（`ExtensionApiManifest`、
`ExtensionMetadata`、`GetExtensionsResponse`、`ExtensionProvides` 枚举）。

### 3.2 扩展包格式

- **传输**：`tar.gz`（`crates/extension_host/src/extension_host.rs:826-861` 用
  `GzipDecoder` + tar 解包）。
- **内容**：必须含 `extension.toml`（缺失时回退 `extension.json`，
  `crates/extension/src/extension_manifest.rs:389-425`）与 `extension.wasm`
  （存在性校验 `crates/extension_host/src/extension_host.rs:1759-1762`）。
- **manifest 必填字段**：`id`、`name`、`version`、`schema_version`，其余 `#[serde(default)]`
  （`crates/extension/src/extension_manifest.rs:84-114`）。
- **schema 版本**：客户端 `CURRENT_SCHEMA_VERSION = SchemaVersion(1)`，接受 `[0]..=1`
  （`crates/extension_host/src/extension_host.rs:75`）。
- **WASM ABI**：**WASM Component Model**（`wasm32-wasip2` + WIT 接口），
  **不是** WASI Preview 1 的普通 cdylib。构建工具链由 `extension_builder` 提供，
  其 WASI SDK 来自 GitHub
  （`crates/extension/src/extension_builder.rs:36`，
  `https://github.com/WebAssembly/wasi-sdk/releases/download/wasi-sdk-25/`）。

### 3.3 本地安装通路（不依赖 zed 服务器）

- **开发扩展**：`install_dev_extension`（`crates/extension_host/src/extension_host.rs:1032`）
  **就地编译**，需要本机具备 cargo / rustup / clang / wasi-sdk；（本机为 OHOS 设备形态，
  这条通路可行性需实测）。
- **预构建目录**：直接把已解包目录放进 `installed/`（目录定义见 `:317-318`、
  `extensions_dir()` 在 `crates/paths/src/paths.rs`），**不需要任何工具链**。
  索引扫描逻辑在 `:1600-1636`。
- 也就是说：**扩展未必要从市场下载**，离线分发是可行的。

### 3.4 兼容性结论

- 接口是 **Zed 私有 REST 协议 + 私有 WASM component ABI**，**不是标准**（无 marketplace
  通用规范；仓库内检索 `marketplace` 零命中）。
- **与 VS Code 市场不兼容**：VSIX 是 Node/JS 扩展模型，Zed 扩展是 wasm32-wasip2 组件，
  两者无法互相加载。
- **没有任何第三方市场与 Zed 兼容**。
- 若要在 OHOS 上去掉市场：改动面在 `crates/extensions_ui`（UI 入口）与
  `crates/extension_host`（拉取逻辑）——注意 `extension_host` 还承担**加载本地已装扩展**的职责，
  不能整块砍掉，否则扩展机制彻底失效。

## 4. 协作（collaboration）

### 4.1 连接建立链路

1. 客户端向 base URL 发 `GET /rpc`（`crates/client/src/client.rs:1301`，`build_url` 直接用 base）。
2. 期待 **302 重定向**，从 `Location` 头取出真正的 collab websocket URL
   （`crates/client/src/client.rs:1310-1322`；非重定向状态即视为错误：
   `"unexpected /rpc response status {}"`）。
3. 用该 URL 建立 websocket 连接（`establish_websocket_connection`，
   `crates/client/src/client.rs:1326` 起），携带 metrics_id / system_id / app_version。
4. 连接成功后 `set_connection`，进入重连/心跳循环（`crates/client/src/client.rs:995-1013` 有
   `"cloud websocket disconnected, will reconnect"` 与重试退避日志）。

可覆盖点：测试用 `ZED_RPC_URL` 环境变量直接指定 rpc URL
（`crates/client/src/client.rs:1298-1300`），避免走 `/rpc` 302 发现流程。

### 4.2 客户端接线点清单（整 crate 移除的改动面）

目标：OHOS 上不编译 `collab_ui`，且不影响其它功能。共 10 处改动点：

- `crates/zed/Cargo.toml:91` —— `collab_ui.workspace = true`，需移入
  `[target.'cfg(not(target_env = "ohos"))'.dependencies]`
  （同文件已有该段的先例：`:246` OHOS 段、`:250` 非 OHOS 段）。
- `crates/zed/src/main.rs:23` —— `use collab_ui::channel_view::ChannelView;`，需加 cfg。
- `crates/zed/src/main.rs:797` —— `collab_ui::init(&app_state, cx);`，**这是全仓库唯一调用
  `title_bar::init` 的地方**（`collab_ui::init` 内部会调 `title_bar::init`，
  `crates/collab_ui/src/collab_ui.rs:23-25`）。因此 OHOS 分支必须补一行
  `title_bar::init(cx)` 兜底，否则标题栏功能丢失。
- `crates/zed/src/main.rs:1361-1372` —— CLI 的 `open_channel_notes` / `join_channel` 处理块
  （含 `Vec::new()` + `ChannelView::open(...)` + `futures::join_all`），需整块 cfg。
  注意：`#[cfg]` **不能**加在 `join!` / `vec!` 的实参上，需用「cfg 双绑定 + 占位 future」的写法。
- `crates/zed/src/zed.rs:785-786` —— `CollabPanel::load(...)`。
- `crates/zed/src/zed.rs:810` —— `add_panel_when_ready(channels_panel, ...)`，位于 `futures::join!` 内，
  同样受「cfg 不能落在宏实参」的限制。
- `crates/zed/src/zed.rs:1300-1306` —— 注册 `collab_panel::ToggleFocus` 动作。

### 5.4 换第三方后的损失（逐项）

**先明确一个前提**：**不能**靠「把 `server_url` 指到第三方」来保住 AI。原因是
`/client/llm_tokens`、`/models`、`/predict_edits/*`、`/web_search` 都是 **Zed 私有协议**，
任何现成的第三方服务（包括 VS Code 生态、OpenRouter 之类的聚合商）都不提供这套接口。
真正可行的路径只有两条：

1. **自建 Zed 协议兼容服务端**（工作量大，且见下面第 5 条，Zeta 依然拿不到）；
2. **改走 BYOK / 本地模型**（这是无自建服务器时的实际选择）。

选择路径 2 之后的损失清单：

1. **Zed AI 托管模型整套**：模型列表、托管推理、LLM token 铸造、用量与计费、组织配额与策略。
2. **Zed 编辑预测（Zeta）**：`zed` provider 完全不可用。
   **这一项即使自建服务端也无法恢复**——Zeta 是 zed 的私有模型权重与服务端能力，
   客户端只有调用协议，没有权重。
3. **Agent 的内置联网检索**：`zed.dev` 是**唯一**的内置 web search provider（见 5.1），
   失去后没有内置替代；要联网只能自建 MCP / context server 工具补。
4. **反馈提交**：`/client/feedback/agent_thread`、`/agent_thread_comments`、
   `/edit_prediction`（`crates/cloud_api_client/src/cloud_api_client.rs:275`、`:290`、`:305`）。
   仅影响「向 zed 反馈」，不影响本地功能。
5. **账号相关页面与能力**：账号页、试用页、升级页
   （`crates/client/src/zed_urls.rs:32-47`）、系统设置同步
   （`/client/system_settings`，`:161`）、试用与订阅状态。
6. **服务端下发的 feature flags**：退回本地 `feature_flags` 设置
   （`crates/feature_flags/src/feature_flags.rs:232-234`）。
   即：某些新功能会因拿不到服务端开关而默认关闭。

### 5.5 换第三方后仍然保留的 AI 能力

- 全部 BYOK 语言模型 provider（14 家，见 5.1 的 `:231-338` 清单）。
- 自定义 OpenAI-compatible / Anthropic-compatible provider（`:193-210`）——
  这一条还允许把任意自建或聚合网关接进来。
- 编辑预测的 5 个非 zed provider：Copilot、Codestral、Ollama、OpenAI-compatible、Mercury
  （`crates/settings_content/src/language.rs:98-116`）。
- Agent 面板本体（会话、工具调用、终端、diff 应用）、规则/profile 文件、
  MCP 与 context server（除 2.6 那一个 OAuth CIMD URL 外无服务器依赖）。
- 本地模型全套（Ollama / LM Studio / LlamaCpp）。

### 5.6 结论

- AI 里唯一「必然失去、无法替代」的是 **Zeta 编辑预测**。
- 「Zed AI 托管模型」与「内置 web search」在自建兼容服务端的前提下**理论可保**，
  但需要自己实现私有协议与（web search 的）检索后端。
- 其余全部可按 provider 切换，**不依赖 zed 官方任何服务器**。

## 7. OHOS 现状盘点

### 7.1 当前构建通道

`crates/zed/RELEASE_CHANNEL` 内容为 `dev`。
构建脚本 `script/bundle-ohos` 中**没有**设置 `ZED_RELEASE_CHANNEL`、
`ZED_MINIDUMP_ENDPOINT`、`ZED_CLIENT_CHECKSUM_SEED`（已检索确认，零命中）。

**复核方法**（备注，便于日后重做）：`grep -n "cargo build" script/bundle-ohos` 先做阳性对照
（命中 `:392` 等 3 处，证明 grep 对该文件有效），再检索上述三个变量得零命中；
仓库内其它构建入口（`.cargo/config.toml`、`install-local.sh`、`build-profile.json5`、
`entry/build-profile.json5`）同样零命中。注意 `script/bundle-ohos` **无扩展名**，
仓库自带的 `psrch.py` 按扩展名过滤，无法覆盖该文件，只能用 grep + 阳性对照的方式复核。

推导出的三条结论：

1. `poll_for_updates()` 返回 false → **不自动轮询更新**。
2. `should_install_crash_handler()` 为 false → **不安装崩溃处理器、不上传 minidump**。
3. 遥测 checksum 头为空。

**OHOS 设置叠加层现状**（`assets/settings/default-ohos.json`，2026-09-22 核对）现有 4 项覆盖：

- `terminal.copy_on_select = true`
- `collaboration_panel.button = false`（协作面板按钮不出现在状态栏）
- `edit_predictions.allow_data_collection = "no"`（编辑预测训练数据无条件不采集）
- `agent.max_content_width = 1128`

其中**没有 telemetry 项** → 遥测仍按上游默认开启（见 §2.1），也没有改 AI provider 默认值
（即 §8 的方案 A/B 均未执行）。

## 10. 一句话备忘

- 官方服务只有一个总闸：`server_url`（默认 `https://zed.dev`）。
- 不登录时只有「遥测」和「扩展市场」会真的发请求。
- 遥测是**默认开**且不需要登录的那个，也是唯一「悄悄在发」的一项。
- AI 里唯一换不掉的是 Zeta 编辑预测；唯一没有替代品的是内置 web search。
- 协作不是「换 URL 就能自建」的轻量服务。
